## 1. 系统概览与技术栈

**一句话**：完全离线的本地文件标签检索工具。Express 单进程后端（SQLite FTS5 全文索引 + chokidar 实时监听 + sharp 缩略图 + SSE 推送）+ React SPA 前端；交付形态为免安装便携包。

| 层 | 技术 | 版本（实际安装） |
|---|---|---|
| 后端运行时 | Node.js | ≥20（便携包内置 Node 22） |
| Web 框架 | express + cors | 4.19 / 2.8 |
| 数据库 | better-sqlite3（含 FTS5 trigram） | 11.10 |
| 文件监听 | chokidar | 3.6 |
| 缩略图 | sharp | 0.33 |
| 前端 UI | react / react-dom | 18.3 |
| 构建 | vite + @vitejs/plugin-react + typescript | 5.4 / 4.3 / 5.6 |
| 状态 | zustand | 4.5 |
| 虚拟滚动 | @tanstack/react-virtual | 3.10 |
| 样式 | tailwindcss + postcss + autoprefixer | 3.4 |
| 测试 | vitest + supertest | 2.1 / 7.0 |

**架构分层**（后端）：`routes/`（HTTP 层，参数校验+统一响应）→ `services/`（业务逻辑）→ `db.ts`（连接与 schema）→ `schema.sql`（表结构）。
**前端数据流**：组件 → `api.ts`（fetch 封装）→ `store.ts`（zustand 单一 store）→ 组件订阅。

**进程内组件**（`server/index.ts`）：Express app、SQLite 连接、chokidar watcher、缩略图生成器、PowerShell 文件夹选择宿主、SSE 广播中心。监听 `127.0.0.1`（不暴露局域网）。

**启动序列**（`index.ts`）：读 config → 打开库并初始化 schema/种子 → `app.listen(port)` → `watchAllIndexed()` 启动监听 → **启动回扫**（后台异步逐目录 `scanDirectoryAsync`，补录关机期间错过的变更，日志 `[TagVault] 启动回扫 N 个目录`）。

## 4. 数据库 Schema

单文件 SQLite：`<dataDir>/tagvault.db`。全部 DDL 在 `server/schema.sql`（含 FTS5 与触发器），要点：

```sql
directories(id, path, path_key UNIQUE, name, last_scanned_at, created_at)
files(id, dir_id→directories, path UNIQUE, name, ext, category,
      size, mtime, missing 0/1, created_at, updated_at)
tag_types(id, name UNIQUE, input_mode 'enum'|'free', sort_order, hidden_in_filter, created_at)
tag_values(id, type_id→tag_types, value, sort_order, UNIQUE(type_id, value))
tags(id, file_id→files, type_id→tag_types, value, created_at, UNIQUE(file_id, type_id, value))
```

**FTS5 全文索引**：`search_fts(text, kind, ref_id)`，trigram tokenizer，`content=''` 外部内容模式。
**同步全靠触发器**（6 组）：files 增删改 → 索引 `name+path`（kind='file'）；tags 增删改 → 索引 `value`（kind='tag'）。字典值改名/移动通过 `UPDATE tags` 触发对应触发器完成 FTS 同步——**业务代码禁止手写 search_fts**。

**种子数据**（`db.ts` 初始化）：9 个预设类型（含两个枚举：保密级别[公开/内部/机密]、版本状态）+ 受保护的「未分类」类型（free 模式）。初始化后执行 `backfillFreeDictValues()`：把历史上只存在于 tags 而未登记 tag_values 的自由值补录进字典（保证所有使用中的值都可在设置中改名/移动/删除）。

**缺失与接力**：`files.missing=1` 表示文件当前不在磁盘上。接力机制见 5.1。

## 5. 后端模块与关键机制

### 5.1 scanner.ts —— 扫描、两阶段入库与移动接力

- `scanDirectory(dirId)`：递归 `fs.stat` → **两阶段**：
  1. 先把该目录下库中有、盘上无的行标记 `missing=1`；
  2. 再处理本次扫描发现的文件（`pendingInserts`）。
  这样 `upsertFileStat` 在插入前能对"刚被标记缺失的行"做 **relink**。
- `relinkMovedFile(dirId, path, ..., size, mtime)`：`SELECT id FROM files WHERE missing=1 AND size=? AND mtime=? AND path!=? ORDER BY updated_at DESC LIMIT 1` —— 命中则 UPDATE 该行的 path/dir_id/name/ext/category/missing=0，**file_id 不变 → 标签全保留**。这是"文件挪动/改名标签不丢"的核心。
- 进度经 `events.ts` 以 SSE `scan-progress` 推送；`scanDirectoryAsync` 为不阻塞启动的后台版本。
- 分类规则：按扩展名映射 image/pdf/word/sheet/ppt/text/video/audio/archive/other。

### 5.2 watcher.ts —— 实时监听

- chokidar 监听全部已索引目录；事件 500ms 合并去抖进 `pending` 队列。
- `flushPending()` **先分类**（消失 vs 存在）→ **单事务**：先标缺失，再 upsert —— 保证移动/改名场景下 relink 生效。
- 变更后广播 SSE `files-changed`；前端收到后防抖刷新列表与 🔔 计数。

### 5.3 tags-service.ts —— 标签业务核心

| 函数 | 行为要点 |
|---|---|
| `addTags(fileId, items)` | 幂等 INSERT OR IGNORE；枚举白名单校验（42201）；自由值自动登记字典；无类型归「未分类」（不存在则创建） |
| `removeTags(fileId, items)` | 类型+值精确删除；枚举值不必在字典内也可删 |
| `batchTag(fileIds, typeId, values, action)` | 单事务。**remove 且 values=[] → 按类型整类去标**（`DELETE FROM tags WHERE file_id=? AND type_id=?`，不校验值）；add 空 values 仍报 42203 |
| `clearAllTags(fileIds)` | 一键清空所选文件全部标签（所有类型），单事务 |
| `suggest(q, limit)` | 跨类型前缀匹配，tags 计数 UNION 字典 0 计数，精确匹配置顶 |
| 类型 CRUD | `createType/updateType/moveType/deleteType`；改名同步 FTS（触发器）；「未分类」保护（40911）；删除需 confirm（40910 带影响数） |
| 字典值 | `addDictValue/renameDictValue/moveDictValue/deleteDictValue`；移动可带走全部已挂标签到已有类型或新建类型；删除级联移除标签 |

### 5.4 folder-picker.ts —— 文件夹选择（解决"特别慢"）

PowerShell 常驻宿主 + **READY 握手**协议：启动时预热 WinForms `FolderBrowserDialog`（STA、TopMost）→ 就绪后写 `READY` 到 stdout → 后端等到 READY 才转发请求（15s 超时降级 COM `Shell.Application`，宿主异常快速回退）。选完路径或取消经 stdout JSON 返回；总超时 600s。

### 5.5 其余服务

- **thumbnails.ts**：sharp 生成 256px webp，缓存名 `sha1(path+mtime)`；URL 带 `?v=<mtime>`，文件变更即自动失效。
- **transfer.ts**：导出 JSON（`{version, types[], tags[]}`）/ CSV（UTF-8 BOM）；导入按**类型名**对齐 upsert，未匹配路径列清单返回。
- **shell.ts**：`start "" "path"` 打开文件；`explorer /select,"path"` 定位。
- **http.ts**：`ok(res, data)` / `wrap(handler)`（捕获 ApiError → 统一错误响应）/ `ApiError(code, message, data)` / `CODE` 常量。

## 6. REST API 全清单（实测）

统一响应：`{ "code": 0, "data": ..., "message": "ok" }`。以下路径均挂 `/api` 前缀。

### 配置与状态

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/config` | → `{port, dataDir, autoOpenBrowser}` |
| PUT | `/config` | `{port?, dataDir?, autoOpenBrowser?}`；改端口需重启 |
| GET | `/status` | `{version, totalFiles, missingCount, scanning, scan?}` |
| GET | `/events` | **SSE**：`scan-progress` / `files-changed` / `scan-done`（data 为 JSON） |

### 目录与扫描

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/directories` | `DirectoryRow[]`（含 fileCount/missingCount） |
| POST | `/directories` | `{path}` → 判重 40901 → 入库并触发扫描 |
| POST | `/directories/:id/rescan` | 手动重扫 |
| DELETE | `/directories/:id?confirm=1` | 不带 confirm → 40910 `{affected, withFiles}` |
| GET | `/scan/status` | 扫描进度 |
| GET | `/directories/pick` | 弹系统文件夹选择框（READY 握手 + COM 兜底）→ `{path|null}` |

### 搜索与 facets

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/search` | 参数：`q`（支持 `类型:值`）、`types`（JSON `{"<typeId>":["值1","值2"]}`）、`categories`（JSON 数组）、`final=1`（只看定稿）、`untagged=1`（只看无标签）、`sort=name\|mtime\|size`、`order=asc\|desc`、`page`、`pageSize`。→ `{total, page, pageSize, items[], facets, parsedConditions}` |
| GET | `/suggest?q=` | 快速添加联想 → `SuggestItem[]`（`{value, typeName, typeId, count, exact}`） |
| GET | `/facets` | `{categories: Record<key,count>, tagTypes: FacetType[]}` |

**搜索语义**：关键词之间 OR；`类型:值` 字段条件解析进 `parsedConditions`；同类型多值 = 或（`value IN (...)`），跨类型 = 且（EXISTS 链 AND）；`untagged=1` = `NOT EXISTS (SELECT 1 FROM tags WHERE file_id=f.id)`；`final=1` = 任意类型标签值 `LIKE '%定稿%'`。≥3 字符子串走 FTS MATCH，短词/CJK 降级 `LIKE`。

### 文件与标签

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/files/:id` | 文件详情（含全部标签） |
| GET | `/files/:id/tags` | 轻量标签列表 |
| POST | `/files/:id/tags` | `{tags:[{typeId?|type?, value}]}` 打标（幂等）；或 `{typeId, values[]}` |
| DELETE | `/files/:id/tags` | 同形参去标 |
| POST | `/files/:id/refresh` | 重 stat 单文件（watcher 缺席兜底） |
| POST | `/tags/batch` | `{fileIds[], typeId, values[], action:'add'|'remove'}` → `{affected}`；**remove+空 values = 整类去标** |
| POST | `/tags/clear` | `{fileIds[]}` → 一键清空全部标签 → `{affected, files}`；空 fileIds → 42203 |

### 类型与字典值

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / POST | `/tag-types` | 列表（含各值 count）/ 新建 `{name, inputMode}` |
| PUT | `/tag-types/:id` | `{name?, inputMode?, hiddenInFilter?}`；改名同步 tags+FTS |
| POST | `/tag-types/:id/move` | `{direction:'up'|'down'}` 排序 |
| DELETE | `/tag-types/:id?confirm=1` | 未确认 40910 `{affectedFiles, valueCount}`；「未分类」40911 |
| POST | `/tag-types/:id/values` | 新增字典值 |
| PUT | `/tag-values/:id` | 改名（同步 tags + FTS） |
| DELETE | `/tag-values/:id?confirm=1` | 级联移除该值全部标签；未确认 40910 |
| POST | `/tag-values/:id/move` | `{toTypeId}` 或 `{newTypeName}`（自动建 free 类型）；带走全部已挂标签 |

### 数据与系统

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/export?format=json\|csv` | 导出（CSV 带 BOM） |
| POST | `/import` | `{data}`（导出 JSON 结构）→ `{restoredTypes, restoredTags, restoredValues, unmatched[]}` |
| GET | `/system/missing` / POST `/system/missing-check` / POST `/system/missing/cleanup?confirm=1` | 缺失列表 / 全量校验 / 清理缺失记录 |
| GET | `/system/untagged` | `{count}` 无任何标签的文件数（🔔 徽标数据源） |
| GET | `/system/stats` | 总量统计 |
| POST | `/system/open-file` / `/system/open-folder` | 系统打开 / 定位所在文件夹 |
| GET | `/thumbs/:fileId?v=<mtime>` | webp 缩略图 |

## 7. 错误码约定

| code | 含义 | 场景 |
|---|---|---|
| 0 | 成功 | — |
| 40404 | 资源不存在 | 文件/类型/字典值 id 无效 |
| 40901 | 目录已存在 | 添加重复路径 |
| 40902 | 名称已存在 | 类型/字典值重名 |
| **40910** | **需二次确认** | 删除类型/字典值/目录/缺失清理；`data` 携带影响数，前端确认后带 `confirm=1` 重发 |
| 40911 | 「未分类」受保护 | 改名/删除未分类类型 |
| 42201 | 枚举白名单外 | 枚举类型打字典外的值 |
| 42202 | 超长 | 标签值 >100 字符 / 类型名 >30 字符 |
| 42203 | 为空 | 标签值/类型名/fileIds 为空 |
| 50000 | 内部错误 | — |

前端 `FRIENDLY_CODES`（store.ts）把这些码映射成短提示；40910 不弹错，由调用方走确认流程。

## 8. 前端架构与状态设计

### store.ts（zustand 单一 store）关键 state

```
检索：query / debouncedQuery(150ms) / selectedTypes{typeId:[values]} / categories[] /
     finalOnly(持久化) / untaggedOnly / untaggedCount(🔔)
结果：items[] / total / page / loading / facets / parsedConditions
多选：selection[] / lastClickIndex（Shift 范围选锚点）
详情：detailId / detail / detailLoading（批量模式由 selection.length>1 推导，不单独存）
弹窗：settingsOpen / contextMenu / toasts[] / scanProgress
```

关键 action：

- `rowClick(e, item, index)`：Shift=范围选；Ctrl=翻转选中（选完以点击项为锚点 `openDetail`，全取消则 `closeDetail`）；单击=单选+打开详情。
- `afterTagMutation()`：任何打标/去标后统一执行 `refreshFacets + runSearch + refreshUntaggedCount + refreshDetail`。
- `runBatchTag(fileIds, typeId, values, action)`：批量接口封装（BatchTagBar 用）。

### 组件交互要点

- **BatchTagBar**：默认（typeId=0）即「不指定类型」→ 未指定时值走「未分类」类型 id（facets 里按名查找）；「未分类」尚未创建时打标降级为逐文件 `POST /files/:id/tags`（后端自动建类型）；整类去标/清空全部标签有 `window.confirm`。
- **DetailPanel 批量模式**：`selection.length > 1` 时切换；≤50 个文件时逐个 `GET /files/:id/tags` 拉并集（detail 对象刷新后重拉），超出只显示锚点文件但操作仍作用于全部；覆盖状态 `all/some/none` 驱动「已挂/部分」徽标与勾选语义。
- **QuickTagInput**：多选时按 payload 的 typeId 分组走 `/tags/batch`，无类型值归「未分类」id，类型缺失时逐文件兜底。
- **useSSE**：`files-changed` → 800ms 防抖刷新列表 + 🔔 计数 + info toast（3s 去重）；`scan-progress` → 进度条。
- 持久化：`localStorage` key 前缀 `tagvault.`（sort/order/view/finalOnly）。

## 9. 测试体系

**框架**：Vitest + Supertest。`tests/setup.ts` 每个测试文件创建**临时目录 SQLite 库** + 独立 Express app 实例，通过 `setDataDirForTest` / `setConfigFileForTest` 隔离，**绝不触碰真实 config.json / 数据目录**（早期曾出现测试污染真实配置的缺陷，已用此钩子根治）。

**用例分布（49 个全绿）**：
- `api.test.ts`（38）：目录判重、扫描入库、打标幂等/枚举白名单/长度/未分类归组、搜索语法与或/且语义、facets、suggest、**整类去标**、**一键清空（含现场恢复）**、类型改名 FTS 同步、字典值改名/移动/删除、导入导出往返、缺失检查与清理、**未打标签筛选与计数**、**只看定稿（任意类型）**、**文件移动/改名接力（file_id 与标签保留）**。
- `query-parser.test.ts`（11）：`类型:值` 解析、全角冒号、或/且、非类型名退化关键词、特殊字符不崩。

**经验教训（写测试时注意）**：清空/去标类用例会改变后续用例的标签前提——需要在用例末尾按原 `(typeId, value)` **恢复现场**；使用独立文件名（如 `接力测试文件.bin`）避免与其他用例的删除操作互相干扰。

## 10. 便携版打包与交付

**产物**：`TagVault-便携版.zip`（~46.4MB）。之所以不做单 exe：better-sqlite3/sharp 为原生模块，采用「**文件夹 + 内置 node.exe**」方案（免安装、免编译）。

**组装结构**：

```
TagVault-portable/
├── 启动标签管家-静默.vbs      # wscript 隐藏启动 launcher.js（内容 ASCII 防 GBK 乱码）
├── 启动标签管家.bat           # 控制台模式启动（关窗即停）
├── 停止标签管家.bat           # 读 app/.running-port 中的 PID 并结束
├── 使用说明.txt / 用户手册.md
└── app/
    ├── node.exe              # 内置 Node 22
    ├── launcher.js           # 启动器（见下）
    ├── dist/                 # 前端产物
    ├── dist-server/          # 后端产物 + schema.sql
    ├── node_modules/         # 生产依赖（express/better-sqlite3/sharp/chokidar…）
    ├── data/                 # tagvault.db + thumbs/（运行生成）
    ├── logs/tagvault.log     # 日志（2MB 轮转）
    └── config.json           # 首次启动生成
```

**launcher.js 行为**：静默模式无控制台（日志重定向到 tagvault.log）；启动前 `probeTagVault` 探测端口 → 已有实例则直接开浏览器（防多开）→ 端口被占则**自动回退下一空闲端口**并写 `.running-port` → 子进程致命错误时 `mshta` 弹窗提示 → `autoOpenBrowser` 打开浏览器。`TV_PORT` 环境变量可覆盖。

**发布流程（每次改码后）**：

```bash
cd TagVault && npm test && npm run build
# 1) 拷 dist/ dist-server/ → TagVault-portable/app/（先删旧的避免残留 bundle）
# 2) Compress-Archive TagVault-portable → TagVault-便携版.zip
```

## 11. 扩展指南：如何加一个功能

以"给文件加备注字段"为例的标准落点：

1. **Schema**：`server/schema.sql` 加列/表（已有库需在 `db.ts` 写迁移逻辑：`PRAGMA table_info` 检查后 `ALTER TABLE`）。
2. **服务层**：`server/services/` 加业务函数（事务用 `withTransaction`；涉及搜索的字段确认是否要进 FTS——通常靠触发器，不要手写）。
3. **路由**：`server/routes/` 挂路由，一律 `wrap()` 包裹、`ok()` 返回；需要确认的操作抛 `ApiError(CODE.NEED_CONFIRM, ..., 影响数)`。
4. **前端 API**：`client/src/api.ts` 加封装函数 + `client/src/types.ts` 对齐类型。
5. **状态**：`client/src/store.ts` 加 state/action；打标类变更记得接入 `afterTagMutation`。
6. **组件**：`client/src/components/` 加 UI；多选场景想清楚"作用于单个还是全部所选"（参照 DetailPanel 批量模式）。
7. **测试**：`tests/api.test.ts` 加用例（注意现场恢复）；`npm test && npm run typecheck`。
8. **交付**：按第 10 节流程同步便携包并重打 zip；更新 `docs/用户手册.md`。

**红线约定**：任何代码不得发起外部网络请求（完全离线）；业务代码禁止手写 `search_fts`（只能通过业务表触发器）；时间一律 epoch 毫秒；路径判重用 `path_key` 归一化键；「未分类」类型名固定且受保护。
